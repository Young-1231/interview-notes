### Java语言有什么特点?（中国建设银行-2023届&&交通银行-2024届春招）
1、跨平台性：Java程序通过JVM（Java虚拟机）执行，编写一次后可以在不同平台上运行，实现了"一次编写，到处运行"的目标。Java的字节码形式使得它能在任何支持JVM的操作系统上运行。
2、面向对象：Java是一种纯面向对象语言，支持类、对象、继承、封装、多态等特性，有助于代码的重用、维护和扩展。除了基本数据类型外，所有内容都是对象。
3、内存管理：Java通过自动垃圾回收机制（GC）来管理内存，开发者不需要手动处理内存分配和释放，从而减少了内存泄漏和指针错误等问题。
4、高性能：尽管Java是解释型语言，但通过JVM的即时编译（JIT）和优化机制，能够提供接近本地语言的执行性能。
5、多种开发模式支持：Java不仅适用于桌面应用和Web开发，还在大数据、分布式系统、云计算等领域有广泛应用。

3、语法和特性：Java是一种严格的面向对象编程语言，几乎所有内容都是对象（除了基本数据类型）。它没有多重继承，使用接口来解决多继承问题。C++支持多重继承，既支持面向对象编程，也支持过程式编程。C++相对于Java来说更为灵活，但也更复杂。
4、性能：Java依靠jvm运行，需要解释执行，C++是直接将代码编译为机器码，执行效率更高为什么web开发通常使用Java：

### Java和Go的区别
1、语言特性：Java注重稳定性、通用性和强大的面向对象特性，适用于大规模、复杂系统的开发。go注重简洁、高效和并发友好，是为现代云原生和高性能场景设计的语言。
2、性能对比：Java运行在JVM上，通过JIT（即时编译）技术优化性能，但因JVM启动时间较长，运行时内存占用较高。线程模型较重，一般需要线程池优化并发。而go直接编译为机器码，启动速度快，运行效率接近C。其Goroutines是轻量级的并发单位，比Java线程占用资源更少，切换成本极低，在高并发场景中表现更优。
3、并发：Java使用多线程模型，通过 Thread 或线程池实现并发，开发复杂度较高，容易出现死锁或资源竞争问题，需配合锁（如 ReentrantLock ）等机制。go内置并发支持，Goroutines和Channels实现CSP（通信顺序进程）模型，天然适合并发编程，代码更加简洁、安全。
4、运行机制：Java跨平台依赖JVM，通过将代码编译为字节码，运行在虚拟机上，能实现一次编写、处处运行的效果，但JVM是一个额外的抽象层，可能影响性能。go属于编译型语言，代码直接编译为平台相关的二进制文件，运行时不需要虚拟机，执行效率更高，但需要为每个平台单独编译

### Java的序列化和反序列化指什么？常见的序列化协议有哪些？JDK自带的序列化协议有什么缺点？
1、什么是序列化和反序列化？
序列化：序列化是将Java对象转换为二进制数据的过程，以便将其保存到磁盘、数据库或通过网络传输。序列化后的数据可以被存储或传输，并在需要时恢复成原来的对象。
反序列化：将二进制数据流还原为对象的过程
2、常见的序列化协议：
Java原生序列化协议：使用 java.io.Serializable 接口标记对象进行序列化。
JSON：基于文本，易读易用，但数据量较大，性能一般。
XML：类似于JSON，具有更强的结构化描述能力，但更冗长。
ProtoBuf：谷歌开源协议，序列化数据紧凑，性能高，适合高效网络通信。
3、jdk自带的序列化协议优缺点：
性能：Java原生序列化生成的二进制数据体积较大，序列化和反序列化的速度相对较慢，尤其在高并发场景中效率低下。
向后兼容性差：如果类的结构发生变化（如新增字段），序列化后的数据可能无法正确反序列化，会抛出 InvalidClassException 。必须显式声明 serialVersionUID 来保证版本兼容，否则会存在隐患。
原生序列化后的数据是二进制形式，人类无法直接理解，调试和排查问题较为困难。且只适用于Java环境，不支持跨语言通信

### 方法重写和重载有什么区别？（中国建设银行-2023届&&邮政储蓄银行-2024届秋招&&中国工商银行-2023届）

### 泛型是什么？为什么会进行泛型擦除？
泛型是jdk5引入的一个新特性，允许在定义类和接口的时候使用泛型作为参数，声明的泛型参数在使用时会用具体的类型替换，使用泛型的好处首先就是方便，假设我们需要将String和Integer放入一个List，如果不用泛型我们需要定义两个list，采用泛型的话，就直接List<T>这一个就可以实现。第二个就是安全，不使用泛型，像刚刚的集合的转换会在运行时检查，如果类型转换出错，程序会直接挂掉，而泛型的作用就是在编译时做类型检查，这就是为什么要做类型擦除补充：什么是泛型擦除？
说简单点泛型擦除就是将泛型Java代码转换为普通Java代码，只不过编译器会直接转换为字节码初始代码：
public class Student<T>{Tbar;
voidadd(Tparam){}};
经过编译器的处理后，会把泛型擦除掉，就变成了：
public class Student{Objectbar;
voidadd(Objectparam){}};

### 接口和抽象类有什么区别
1、方法定义：接口中只是定义了一些方法而已，接口中只有抽象方法，没有具体的实现代码。
2、修饰符：抽象类的修饰符和普通class类一样，接口默认只能使用public
3、构造器：抽象类可以有构造器，接口不行
4、接口只能被实现，抽象类可以被继承
5、一个类可以实现多个接口，但只能继承一个抽象类，接口支持多重继承
6、接口和抽象类的职责不一样，接口主要用于定制规范，而抽象类的主要目的就是为了复用，最典型的就是模版方法模式

### Java中final和finally有什么区别？finally代码块一定会被执行吗？
final：在修饰类的时候，表明该类不可以被继承，修饰方法的时候表示不能被重写，修饰变量的时候表明变量是常量，值不能被修改。对于引用类型变量，引用地址不可变，但对象的内容可以修改。

### 解释一下Java中的栈和队列
栈是一种后进先出的数据结构，最后放入的数据优先被取出，push操作时会将元素压入栈顶，Pop操作时会从栈顶移除元素，Peek获取栈顶元素但不移除；Java中可以使用Stack或者ArrayDeque来实现栈，推荐使用ArrayDeque；
队列是一种先进先出的数据结构，最先放入的数据最先被取出，元素入队时会将元素添加到队尾，取出的时候会从队尾将元素移除，Java中提供了Queue接口和多种实现实现队列，推荐使用ArrayDeque实现双端队列，更高效

### 什么是成员变量？什么是局部变量？
成员和局部其实就是一个作用于范围，局部变量就是定义在方法或者构造器或者代码块里面的变量，这个变量只在该方法或者该构造器或者该代码块中有效，在该作用域执行结束后，会自动销毁，变量创建时会存储在栈内存中成员变量的作用范围是在整个类中有效，成员变量根据声明位置可以分为静态变量和实例变量，定义在类中，但在方法、构造器或者代码块之外，整个类中的任何位置都可以使用这个变量，实例变量会存储在堆中，因为是属于对象，静态变量存储在方法区，属于类，实例变量在对象销毁时释放内存，静态变量在类卸载时释放内存

### 什么是静态变量？为什么静态方法不能调用非静态成员？
静态变量是通过 static 关键字声明的变量，属于类，所有类的实例共享一个静态变量，在类加载时进行初始化，并且在程序运行期间会一直存在，直到程序结束或者类卸载，java8之前存储在方法区，java8之后存储在元空间静态方法是类级别的，而非静态成员是对象级别的，所以静态方法在类加载的时候就会被分配内存，此时可以直接被访问，不需要实例化对象；非静态成员只有在对象被创建时才会分配内存，比较依赖于具体的对象的状态所以在静态方法执行时候的，对象可能还没有实例化，所以无法访问

### 说说深拷贝，浅拷贝和引用拷贝之间的区别
引用拷贝：直接复制对象的引用，而不是复制对象本身。两个变量指向同一块内存地址。那么此时，当修改任意一个变量的内容，另一个变量也会随之改变，并且不会产生新的对象，仅增加引用计数。缺点就是两个对象耦合，容易出现意外修改浅拷贝：复制对象本身及其基本类型的字段，但不会递归复制引用类型字段，引用类型字段仍然指向原对象的内存地址。也就是说原对象和拷贝对象的基本类型字段是独立的，但引用类型字段指向相同的内存，那么此时修改引用类型字段的数据会影响另一个对象，缺点就是无法彻底隔离两个对象，容易出现数据联动。
深拷贝：递归复制对象本身及其所有引用类型字段，确保新对象与原对象完全独立。
原对象和拷贝对象完全独立，修改任意一方不会影响另一方。那么此时就会需要更多的内存和时间开销

### Java中有哪些访问修饰符？作用范围是怎样的？
 `public`    - 定义：最开放的访问修饰符。
   - 作用范围：可以被任何地方访问，包括不同的包。
 `protected`    - 定义：允许在同一个包内以及通过子类继承的方式访问。
   - 作用范围：
      - 当前类。
      - 同一个包中的其他类。
      - 不同包中的子类
 `default`    - 定义：如果没有显式声明访问修饰符，则默认为 default ，也称包级访问。
   - 作用范围：仅限于同一个包内，不能被不同包中的类访问。
 `private`    - 定义：最严格的访问控制修饰符。
   - 作用范围：仅限于当前类内访问。

### 构造器能被重写或者重载吗
构造器不能被重写，重写是子类对父类方法的重新定义，要求方法签名相同。构造器本质上不是普通方法，而是用来初始化对象的特殊方法，不能继承到子类。类可以通过 super()
调用父类的构造器，但这不是重写。
构造器可以被重载，同一个类中可以定义多个方法名相同但参数列表不同的方法，实现不同参数组合的初始化需求

### 讲讲Java值传递，你觉得为什么Java没有引用传递
值传递：将变量的值的副本传递给方法。方法接收到的是一个副本，对副本的修改不会影响原始变量。
引用传递：将变量的引用（内存地址）传递给方法。方法中对该引用的修改会直接影响到原始变量。
没有引用传递的原因：从安全性和可维护性的角度说，如果Java支持引用传递，修改方法参数中的引用变量可能会直接影响原始对象或变量，导致意想不到的错误，增加了程序调试的难度。另外java中，传递对象引用时，传递的是引用的副本，并不是原始引用本身，虽然可以通过副本引用修改对象的属性，但不能通过副本引用改变原始引用的指向。所以总的来说就是为了化内存管理、避免潜在的混乱和错误，保证程序的安全性和可维

### hashMap底层？扩容机制？为什么扩容使用2的n次方倍？默认负载因子为什么是0.75？什么时候

HashMap底层结构：HashMap是基于数组+链表/红黑树实现的。当我们通过一个键值对进行插入时，首先计算该键的哈希值，根据哈希值定位到数组的一个索引。如果该位置为空，就直接存储；如果有冲突，则形成链表（Java1.7）或红黑树（Java1.8）。
扩容机制：HashMap的扩容是基于负载因子的。默认负载因子为0.75，当元素数量超过当前容量的0.75时，会触发扩容。扩容是将容量扩大为原容量的2倍，这样做是为了减少hash冲突并保持散列性能。
为什么扩容使用2的n次方倍：扩容时使用2的n次方倍是为了保证哈希桶的下标计算更加高效。哈希表大小为2的n次方时，通过与容量-1做按位与操作（ index = hash &(capacity - 1) ），可以高效地计算出元素应该存储在哪个桶中。
负载因子默认值是0.75：0.75是在空间和时间复杂度之间的平衡值。设置负载因子为0.75意味着当HashMap已经存储的元素达到总容量的75%时，HashMap会扩容。如果负载因子设置得太高，HashMap会频繁扩容；太低则浪费内存。
链表转化为红黑树的条件：在JDK1.8中，如果某个桶中的链表长度超过8且数组的容量大于64，链表会转换为红黑树。红黑树是自平衡的二叉搜索树，可以提高查找效率。
红黑树的好处：红黑树是一种平衡的二叉搜索树，保证了插入、删除和查找操作的时间复杂度为O(logn)，相较于链表的O(n)，在处理大量数据时性能大大提高。
红黑树退化为链表的情况：如果桶中的元素个数较少（小于6），红黑树会退化为链表，减少不必要的内存开销。
JDK1.7和1.8的区别：JDK1.7中，HashMap使用链表存储冲突的元素；JDK1.8引入了红黑树，当链表长度超过8且桶的数量大于64时，链表会转化为红黑树。
线程安全问题：HashMap在多线程环境下是非线程安全的。若多个线程并发修改HashMap结构，可能会导致死循环、数据丢失等问题。例如，当多个线程同时向HashMap插入元素时，可能会发生扩容冲突，导致链表或者红黑树的结构不一致。
HashMap死循环问题：当多个线程并发修改HashMap且触发扩容时，可能会造成链表指向错误，导致死循环。为避免这种情况，可以使用 ConcurrentHashMap 。
Put操作流程：HashMap的put操作首先计算键的hash值，定位到对应的桶，然后进行以下操作：
1. 如果桶为空，则直接存储。
2. 如果桶中已有元素，检查是否与现有元素相等。如果相等，替换旧值；如果不等，则形成链表或红黑树。
3. 检查是否需要扩容哈希碰撞的处理：当多个键经过哈希函数计算后映射到同一个桶时，称为哈希碰撞。
HashMap采用链表或红黑树来解决碰撞。
HashMap遍历方式：HashMap有三种遍历方式：
1. keySet()：返回一个Set视图，包含所有的键。
2. values()：返回一个Collection视图，包含所有的值。
3. entrySet()：返回一个Set视图，包含所有的键值对。

### concurrentHashMap为什么是线程安全的？jdk1.7和1.8的实现有什么不同？（交通银行-2022届春招&&饿了么）
线程安全的原因： ConcurrentHashMap 通过分段锁（JDK1.7及之前）或桶级锁（JDK
1.8）机制保证了线程安全。每个桶可以独立锁定，避免了全局锁的竞争，提高了并发性能。
JDK1.7与1.8的实现区别：
- JDK1.7：使用了分段锁，每个分段独立加锁。
- JDK1.8：采用了桶级锁，每个桶都有自己的锁。通过 CAS （Compare And Swap）机制实现锁的细粒度控制，并在必要时引入了红黑树来提升性能。

### 讲讲JVM内存结构？（中国农业银行-2023届&&交通银行-2024届秋招）
方法区（Method Area）：存储类的信息、常量、静态变量、即时编译器编译后的代码等。

### 垃圾回收算法有哪些？各自有什么优缺点
常见的垃圾回收算法有：
- 标记-清除（Mark-Sweep）：
   - 优点：实现简单。
   - 缺点：标记阶段和清除阶段时间较长，容易产生内存碎片。
- 复制算法（Copying）：
   - 优点：效率较高，不会产生内存碎片。
   - 缺点：需要额外的内存空间（通常为原来的一半），不适用于大对象的回收。
- 标记-整理（Mark-Compact）：
   - 优点：能减少内存碎片。
   - 缺点：清理过程复杂，耗时较长。
- 分代回收（Generational GC）：
   - 优点：通过分代的方式提升回收效率。将堆分为年轻代和老年代，分别采用不同的回
收算法。
   - 缺点：老年代回收速度相对较慢。

### 如何判断哪些对象能够被回收？对象能够被回收，就代表一定会被回收吗？
如何判断哪些对象能够被回收：
- 可达性分析：通过GCRoot对象作为起始点，遍历所有可以从GCRoot访问到的对象，无法被访问到的对象就是垃圾对象。
- 引用计数法：每个对象都有一个引用计数器，当计数器为0时，表示没有活跃的引用指向该对象。
是否一定被回收：对象可回收并不代表一定会被回收。GC的回收过程受到许多因素影响，如JVM的内存分配策略、GC策略等，某些对象可能会在多次GC周期后仍然没有被回收。

- 方法区中的类静态属性：类加载器持有的类信息。
- 活动的线程：当前正在执行的线程。
- JNI（Native）引用：本地方法栈中持有的引用。

### 为什么Java可以一次编译处处运行

### 方法区，永久代，元空间的区别，为什么要将永久代替换成元空间？（邮政储蓄银行-2024届秋招&&拼多多&&华为&&得物）
方法区（Method Area）：JVM的内存区域，用于存储类信息、常量、静态变量等内容。
永久代（PermGen）：JVM内存的一部分，存储类信息、常量池、静态变量等。永久代的大小是固定的，如果JVM运行时需要加载过多的类，容易导致 OutOfMemoryError 。
元空间（Metaspace）：JDK8及以后引入的替代永久代的内存区域。与永久代不同，元空间不受JVM堆大小的限制，直接使用本地内存（Native Memory），因此可以动态调整大小。
替换原因：永久代的固定大小和内存管理的问题导致了内存溢出，而元空间可以动态调整大小，使用本地内存，更加灵活。

### JDK中有哪些引用类型，分别有什么特点？
Java中有四种引用类型：
- 强引用（Strong Reference）：最常见的引用类型，普通的对象引用，如 Objectobj = new Object() 。只要强引用指向对象，它就不会被垃圾回收。
- 软引用（Soft Reference）：在内存不足时，软引用指向的对象会被回收，但如果内存足够，软引用指向的对象不会被回收。适用于缓存。
- 弱引用（Weak Reference）：弱引用指向的对象只要被垃圾回收器发现，就会被回收，适用于需要和GC关联的场景。
- 虚引用（Phantom Reference）：虚引用指向的对象已经快要被回收，但可以在对象被回收时做一些后续处理。虚引用几乎不会直接用在程序中。

- 访问类的静态字段。
- 调用类的静态方法。
- 通过反射调用类的方法。
- 初始化一个类的子类时，如果父类没有被初始化，子类会触发父类的初始化。
- JVM要求进行动态代理时，代理类的加载也会触发初始化。

### 为什么程序计数器是线程私有的
程序计数器是线程私有的，因为每个线程执行不同的代码，每个线程都有独立的执行路径。程序计数器保存了每个线程当前执行的字节码的地址，这对于线程切换和恢复执行非常重要。由于不同线程可能执行不同的方法或代码块，因此需要为每个线程提供一个独立的程序计数器，以避免线程间的干扰。

### 垃圾回收器有哪些？（邮政储蓄银行-2024届秋招&&拼多多）
Serial Garbage Collector：使用单线程进行垃圾回收，适用于单核处理器或内存较小的应用。
Parallel Garbage Collector：采用多线程进行垃圾回收，适合多核处理器系统，提供了较好的吞吐量。
Concurrent Mark-Sweep(CMS)Garbage Collector：旨在减少垃圾回收的停顿时间，适用于对响应时间要求较高的应用。CMS采用多线程并发标记和清除。
G1 Garbage Collector：JDK7引入的低延迟垃圾回收器，能够提供更可预测的停顿时间，并在大堆内存和多核系统上提供更好的性能。它通过将堆划分为多个小区域来进行回收。
ZGC(Z Garbage Collector)：一种低延迟垃圾回收器，适用于大内存（TB级别）系统，目标是极低的停顿时间。
ShenandoahGC：与ZGC类似，致力于低延迟，能够在不暂停应用线程的情况下进行垃圾回收。

### 谈谈你对CMS和G1垃圾回收器的理解？G1垃圾回收器相对于CMS有什么好处"（邮政储蓄银行-2024届秋招&&拼多多&&滴滴）
CMS垃圾回收器：
- 特点：CMS垃圾回收器采用并发标记-清除的方式，旨在降低应用的停顿时间，特别适用于需要低延迟的场景。通过多线程并发进行标记和清除，减少停顿时间。
- 缺点：CMS可能会在回收过程中产生碎片，需要Full GC来清理碎片，导致长时间停顿。
G1垃圾回收器：
- 特点：G1垃圾回收器通过将堆划分为多个区域（Region），进行分区域的回收，可以灵活控制停顿时间。它可以根据应用的需求自适应调整回收策略，并且支持预测和设置最大的停顿时间。
- 优点相对CMS：G1在回收时能更精确地控制停顿时间，提供更一致的性能。G1避免了CMS的内存碎片问题，通过精确回收策略，保证了对大内存系统的更好支持。G1支持增量回收，不会像CMS那样依赖于Full GC清理碎片。

### 对象的分配策略是怎样的
对象的分配策略主要基于JVM的堆内存划分：
- 年轻代（Young Generation）：大部分新创建的对象会首先在年轻代分配，年轻代的内存分为Eden区和两个Survivor区（S0和S1）。新对象首先分配到Eden区，当Eden区填满时，会触发Minor GC，将存活的对象从Eden区复制到Survivor区。
- 老年代（Old Generation）：当年轻代的对象经过多次Minor GC仍然存活时，会被晋升到老年代。老年代主要存放生命周期较长的对象。
- 大对象：如果一个对象的大小超过了年轻代的大小阈值，它会直接分配到老年代，避免了在年轻代中频繁的垃圾回收。
- 长期存活的对象：一般会在经历一定次数的GC后从年轻代晋升到老年代

### JDK7为什么要把字符串常量池移到堆中
在JDK7之前，字符串常量池位于方法区。随着JDK7的发布，字符串常量池被移到了堆内存中，主要是为了以下原因：
- 内存管理更灵活：堆内存可以动态调整大小，而方法区的内存通常较为固定，不能根据需求进行调整。
- 解决内存溢出问题：在JDK7之前，方法区的内存有限，容易导致OutOfMemoryError: PermGen space ，将常量池移到堆内存中可以避免这一问
- 题。便于GC管理：堆内存中的对象可以参与垃圾回收，而方法区的常量池无法有效地回收，可能导致内存泄漏。

### 运行时数据区哪些地方会发生OOM异常，分别是因为什么原因？（中国银行-2023届秋招&&阿里&&交通银行-2023届春招）
OOM（OutOfMemoryError）异常通常发生在以下几种情况：
- 堆内存溢出（ java.lang.OutOfMemoryError: Java heap space ）：当JVM的堆内存不足以存放新的对象时会发生。可能是因为对象创建过多、内存泄漏或堆的设置太小。
- 方法区溢出（ java.lang.OutOfMemoryError: PermGen space 或Metaspace ）：JDK7及之前版本使用的方法区（PermGen space）容量有限，类的加载过多或类加载器泄漏可能导致方法区溢出。JDK8之后，方法区被元空间（Metaspace）替代，元空间的溢出通常是因为类加载过多或内存配置不足。
- 栈溢出（ java.lang.StackOverflowError ）：当线程的栈内存超出限制时，会发生栈溢出，通常是递归调用过深或栈的内存分配过小。
- DirectMemory溢出：对于NIO（NewI/O）操作，如果本地直接内存不足，也可能抛出OutOfMemoryError 。

### 类加载的过程是怎样的？
类加载的过程通常包括以下步骤：
1. 加载（Load）：从类的全限定名（包括路径）加载类的字节码。通过类加载器读取字节码，并将其转换为JVM内部的类对象。
2. 验证（Verify）：对字节码进行验证，确保其符合JVM的规范，防止出现非法的字节码（如篡改过的类）。
3. 准备（Prepare）：为类的静态变量分配内存，并赋予初始默认值。
4. 解析（Resolve）：将类中的符号引用（如方法、字段等）转换为直接引用（即内存地址）。
5. 初始化（Initialize）：执行类的静态初始化块（static 代码块）以及静态变量的赋值操作，完成类的初始化。

### 双亲委派机制是什么，有什么好处?怎么打破双亲委派模型
双亲委派机制：JVM的类加载器采用双亲委派模型，子加载器在加载类时会首先委托给父加载器加载。如果父加载器无法加载，则由子加载器尝试加载。这可以确保Java类的加载顺序和类的唯一性。

### 谈谈对内存泄漏的理解，哪些情况会导致内存泄漏？（中国银行-2023届秋招&&阿里）
内存泄漏指的是程序中不再使用的对象仍然被引用，导致无法被垃圾回收器回收，从而导致内存占用逐渐增大，最终导致内存不足。
常见导致内存泄漏的情况：
- 静态集合类：如果某个类的静态变量持有大量对象的引用，且这些对象在实际应用中不再使用，就会导致内存泄漏。
- 事件监听器：如果没有正确地移除事件监听器，可能会导致相关对象无法被垃圾回收。
- 线程池：线程池中的线程如果没有正确关闭，可能会导致线程无法释放，进而导致内存泄漏。
- 外部库的引用：某些第三方库可能没有正确处理对象的销毁，导致对象无法被回收。

### 有哪些常见的GC？谈谈你对Young GC和Full GC的理解，什么时候会发生这两种GC"（交通银行-2024届春招&&字节&&中国农业银行-2024届秋招）
常见的GC：
- Minor GC：发生在年轻代，通常在Eden区填满时触发。
- Full GC：发生在整个堆上，涉及年轻代和老年代的回收，通常发生在内存不足时。
- Young GC：在年轻代发生的GC，清理Eden区和Survivor区中的垃圾对象。
- Old GC：在老年代发生的GC，处理长期存活的对象。
Young GC与Full GC：
- Young GC：触发时仅回收年轻代，通常停顿时间较短，适合快速回收。
- Full GC：触发时会回收整个堆，时间较长，通常在老年代无法容纳更多对象时发生。

### 基本数据类型存放在什么地方？（中国农业银行-2024届秋招&&淘天（说说堆的理解））
基本数据类型在Java中的存放位置有以下几种情况：
- 栈内存：方法栈中的局部变量（如基本数据类型的变量）会被存放在栈内存中。栈内存是自动管理的，方法执行完后会自动销毁这些变量。
- 堆内存：如果是基本数据类型的包装类（例如 Integer 、Double 等），它们会存放在堆内存中。这是因为包装类本身是对象，而对象总是存储在堆中。
- 常量池：对于某些值如 final 常量，JVM可能会将这些值缓存到常量池中，以避免重复创建。

### new String(""shutiaoge"")会在哪些地方创建对象？intern()方法有什么作用
new String("shutiaoge")会在哪些地方创建对象：
1. 堆内存：调用 new String("shutiaoge") 时，会在堆内存中创建一个新的String 对象。
2. 字符串常量池： "shutiaoge" 是一个字符串字面量，它会首先检查字符串常量池中是否已有该字符串，如果没有，就将该字符串放入常量池。如果已有，那么不会创建新的对象，而是引用池中的对象。
所以， new String("shutiaoge") 在堆中创建了一个新的String 对象，而字符串常量池中也会有一个相同内容的 String 对象。
intern()方法的作用： intern() 方法会检查字符串常量池中是否已经包含了当前字符串，如果包含，则返回常量池中的引用；如果没有， intern() 会将该字符串添加到常量池中，并返回这个新创建的对象的引用。
该方法主要用于节省内存，因为常量池中的字符串会被多个地方共享，而 String 对象的常量池保证了不会重复创建相同内容的字符串。

### 什么是直接内存？
直接内存是指JVM堆外的内存区域，Java通过 java.nio 包提供了直接内存访问的能力。
直接内存主要通过 ByteBuffer.allocateDirect() 方法分配，它不属于JVM的堆内存和栈内存，因此不会受到垃圾回收的影响。
- 特点：
   - 与堆内存的关系：直接内存是JVM管理的内存以外的部分，通常是通过操作系统直接
分配的内存。
   - 性能优势：直接内存可以减少从JVM堆内存到操作系统本地内存的复制，提高I/O操作
的性能，尤其是在处理大量数据时。
   - 缺点：直接内存的管理较复杂，需要手动释放，并且过多的直接内存使用可能会导致
OutOfMemoryError 异常。

### 如果发现JVM在频繁fullgc，可能是什么原因导致的，如何进行排查
老年代空间不足：频繁的Full GC通常是因为老年代的空间不足，无法容纳新的对象。可能是老年代的对象在长期存活下去后占用了过多内存。
内存泄漏：某些对象长期存在但无法被垃圾回收（如静态集合类、单例模式、线程池等持有的对象），导致内存无法释放，从而触发频繁的Full GC。
GC配置不当：JVM参数配置不合理，比如老年代的堆内存设置过小，或者新生代和老年代的比例设置不当，可能导致频繁发生Full GC。
高负载下的内存碎片：频繁的对象创建和销毁可能导致内存碎片，使得老年代的内存无法有效使用，最终导致Full GC。
长时间的Full GC：长时间的Full GC可能会导致堆内存中的一些对象长时间无法被清理，进一步加剧内存不足问题。
排查步骤：
1. 查看GC日志：启用 -XX:+PrintGCDetails 和 -XX:+PrintGCDateStamps 参数，分析GC日志，查看频繁Full GC发生的时间点、原因以及内存使用情况。
2. 分析内存占用：通过 jmap 或 VisualVM等工具生成堆dump文件，分析堆内存的占用情况，检查是否有大量无用的对象存在，是否存在内存泄漏。
3. 调整JVM参数：
   - 增大老年代的内存：例如，通过-Xmx 和 -XX:NewRatio 来调整新生代和老年代的
比例。
   - 优化垃圾回收器的配置：例如，选择合适的垃圾回收器（如G1GC）或调整 -
XX:+UseConcMarkSweepGC 等参数。
4. 检查代码中的内存泄漏：检查应用中的静态集合、缓存、线程池等对象的生命周期管理，确认是否存在未及时释放的对象。

对象创建过程：
1. 加载类：类加载器加载目标类的字节码到内存中，准备创建对象。

### 讲讲对乐观锁和悲观锁的理解，通常有哪些实现方式
悲观锁：假设会发生冲突，因此每次访问共享资源时都会对其加锁，确保在操作过程中没有其他线程能够访问。悲观锁的核心思想是“防止并发”。
- 实现方式：
   - synchronized：Java中最常见的悲观锁，通过 sychronized 关键字可以保证代码
块或方法在同一时刻只有一个线程能够执行。
   - ReentrantLock：更灵活的锁，可以手动加锁、释放锁，支持公平锁和非公平锁。
乐观锁：假设不会发生冲突，因此在操作共享资源时不加锁，而是通过版本号或CAS（Compare and Swap）等机制检测是否有其他线程修改数据。如果有冲突，则重试操作。
乐观锁的核心思想是“允许并发，但检测冲突”。
- 实现方式：
   - CAS（Compare-And-Swap）：通过原子操作实现数据的比较与交换，广泛应用于
无锁数据结构。
   - 版本号机制：每次修改数据时更新版本号，在提交修改前检查版本号是否一致，如果
不一致则说明有并发修改，操作失败。

### 线程的状态有哪些？（中国农业银行-2023届&&招商银行-2022届）
线程在生命周期中可能处于以下几种状态：
- New（新建状态）：线程被创建后，尚未开始执行。
- Runnable（可运行状态）：线程可以被操作系统调度执行，实际上可能正在执行。
- Blocked（阻塞状态）：线程正在等待获取某个锁（同步块或方法），但当前锁被其他线程持有。
- Waiting（等待状态）：线程主动进入等待状态，如调用 wait() 、 join() 、sleep() 等方法。
- Timed Waiting（超时等待状态）：线程进入等待状态并指定超时时间，例如Thread.sleep(1000) 或 Object.wait(1000) 。
- Terminated（终止状态）：线程执行完成或因异常终止。

### wait和sleep有什么区别？（中国农业银行-2023届&&招商银行-2022届）
wait()：
- wait() 是 Object 类的方法，线程调用 wait() 时会释放对象的锁并进入等待队列，直到被其他线程唤醒。

- 需要在同步块或同步方法中调用。

- sleep() 是Thread 类的方法，线程调用sleep() 时会让出CPU资源，并且在指定时间后自动恢复执行。
- 不会释放对象锁，因为它不是依赖于对象的锁。
- 可在任何地方调用，不需要在同步块中。

### 怎么理解并行和并发？（中国银行-2023届秋招&&淘天&&招商银行-2022届）
并发：指多个任务在同一时间段内交替执行，可能是同一时间某些任务在执行，某些任务在等待。这种场景下，系统可能只有一个CPU核心，但由于操作系统的调度，任务被交替执行。并发是任务在时间上重叠，不一定在同一时刻执行。
并行：指多个任务在同一时刻同时执行，通常要求多核CPU支持。在并行处理下，任务确实是同时执行的。

### 死锁产生需要满足什么条件？如何检测死锁？"（邮政储蓄银行-2024届秋招&&滴滴三面）
死锁的四个必要条件：
1. 互斥条件：至少有一个资源必须处于非共享模式，即一次只能由一个线程使用。
2. 请求与保持条件：一个线程持有资源，同时请求另一个被其他线程占用的资源。
3. 不可剥夺条件：已获得的资源在未使用完之前，不能被其他线程强行夺走。
4. 循环等待条件：多个线程形成一种头尾相接的循环等待关系。
检测死锁的方法：
- 使用 jstack 获取线程栈信息，分析是否存在线程相互等待的死锁情况。
- 通过JVM的工具（如 jconsole 、visualvm ）来检测死锁。
- 采用死锁检测算法，例如使用图模型检测循环等待。

### 为什么会出现线程安全问题
线程安全问题通常是由于多个线程访问共享资源时没有正确的同步机制，导致竞态条件、数据不一致或异常。常见的原因包括：
- 竞态条件：多个线程并发修改共享数据，造成不一致的结果。
- 缺少同步机制：多个线程在访问共享资源时没有使用锁或其他同步机制来控制访问。
- 内存可见性问题：一个线程对共享数据的修改没有立即对其他线程可见，导致数据不一致。

### 进程和线程有什么区别？为什么要使用多线程？（邮政储蓄银行-2024届秋招&&滴滴一面&&华为）
进程：
- 进程是资源分配的单位，每个进程拥有独立的地址空间、代码和数据。
- 进程间的通信需要使用进程间通信（IPC）机制。
线程：
- 线程是程序执行的最小单位，多个线程共享进程的内存空间和资源。
- 线程间通信相对更容易，通常通过共享内存、管道、消息队列等方式。
使用多线程的原因：
- 提高程序的效率和响应速度：通过并发执行多个任务，充分利用多核CPU。
- 提高资源利用率：通过线程共享进程的资源，避免重复的资源开销。
- 实现异步操作：比如I/O操作、定时任务等，可以避免程序阻塞，提升用戶体验。

### 开启线程应该调用什么方法，为什么不用run()方法
应该调用 start() 方法：调用start() 方法后，JVM会启动新的线程并调用run() 方法。 start() 方法实际上会创建一个新的线程来执行任务，保证并发执行。
不能直接调用 run() 方法：直接调用 run() 方法会在当前线程中执行 run() 的内容，并不会开启新线程。 run() 方法只是一个普通的方法调用，不会实现多线程并发执行。

### 什么是虚拟线程（Java21新特性）
虚拟线程（Virtual Threads）是Java21引入的一个新特性，它是为了支持更轻量级的并发模型而设计的。虚拟线程是比传统的操作系统线程更轻量、可管理的线程，目的是大规模并发任务的执行（如I/O密集型应用）。
虚拟线程的特点：
- 轻量级：虚拟线程的创建和销毁比传统的线程更加快速和低成本。
- 调度机制：虚拟线程的调度由JVM管理而非操作系统，允许在同一操作系统线程中运行多个虚拟线程。
- 高并发：可以创建成千上万的虚拟线程，而不会像传统线程那样消耗过多的系统资源。
- 兼容性：虚拟线程能够与现有的Java应用兼容，支持传统的 ExecutorService 等并发工具。
使用场景：虚拟线程非常适合大量并发I/O密集型任务，如处理HTTP请求、数据库访问等。

### Java的线程同步机制有哪些
Java提供了多种线程同步机制，以保证多线程环境下的线程安全：
- synchronized：Java内置的锁机制，用于修饰方法或代码块，确保同一时刻只有一个线程能够执行被修饰的代码块。
- Lock接口（如 ReentrantLock ）：比 synchronized更灵活，提供了显式的加锁和解锁操作，并支持公平锁、重入锁、定时锁等特性。
- volatile：用于修饰变量，确保对该变量的写操作对所有线程可见，避免因缓存一致性问题引发错误。
- 读写锁（ ReadWriteLock ）：允许多个线程并发地读取数据，但在写操作时会排斥所有其他线程的读取和写入操作。常用的实现是 ReentrantReadWriteLock 。
- 信号量（Semaphore）：控制访问特定资源的线程数量，用于控制并发访问的数量。
- 条件变量（Condition）：与 Lock配合使用，提供线程间的协调和通信，类似于wait / notify 机制，但更灵活。

### 线程池有什么好处？创建方式有哪些？自定义线程池有哪些核心参数？执行流程是怎样的拒绝策
略有哪些？通常是根据什么去定义的？是否能动态调整？线程池如何优雅关闭？线程池中的线程出现异常会发生什么？"（交通银行-2024届春招&&淘天&&阿里云）
线程池的好处：
- 减少资源消耗：避免了频繁创建和销毁线程的开销。
- 提高响应速度：线程池可以复用已有线程，减少了任务等待时间。
- 控制线程数量：通过线程池管理线程数量，避免系统因为创建过多线程而出现性能问题。
线程池的创建方式：
- 使用 Executors 工厂类创建线程池，如：
   - Executors.new FixedThreadPool(int nThreads) ：固定大小线程池。
   - Executors.new CachedThreadPool() ：可缓存线程池，线程池大小根据需求
动态调整。
   - Executors.new SingleThreadExecutor() ：单线程池，只有一个工作线程。
   - Executors.new ScheduledThreadPool(int corePoolSize) ：定时线程
自定义线程池的核心参数池。 ：
- corePoolSize：核心线程池大小。
- maximumPoolSize：线程池最大线程数。
- keepAliveTime：非核心线程空闲时的最大存活时间。
- workQueue：阻塞队列，用于存储等待执行的任务。
- threadFactory：用于创建新线程的工厂。
- handler：拒绝策略，决定当线程池无法处理任务时的行为。
执行流程：
- 线程池接受提交的任务并通过线程池中的线程进行处理。如果所有线程都在执行任务并且队列已满，则根据拒绝策略处理新的任务。
拒绝策略：
- AbortPolicy：丢弃任务并抛出异常。
- CallerRunsPolicy：由提交任务的线程来执行该任务。
- DiscardOldestPolicy：丢弃最旧的任务，执行当前任务。
- DiscardPolicy：丢弃当前任务。
定义依据：线程池的参数通常根据任务的特点、系统资源（如CPU和内存）以及任务的优先级来定义。
动态调整：线程池通过 ThreadPoolExecutor 提供了动态调整核心线程数和最大线程数的功能，可以通过 setCorePoolSize 和setMaximumPoolSize 来调整线程池的配置。
优雅关闭：
- 使用 shutdown() ：开始拒绝新的任务并等待已提交任务的完成。
- 使用 shutdownNow() ：立即停止所有正在执行的任务并返回未执行的任务。
线程池中的线程异常：线程池中的线程若抛出异常，不会影响其他线程的执行，但会导致任务的执行失败。通常，可以通过为任务实现 UncaughtExceptionHandler 来处理异常，或通过 submit() 方法来捕获异常。

### volatile关键字是为了解决什么问题？它可以保证原子性吗，为什么？（中国农业银行-2024届秋招&&滴滴）
解决的问题：
- volatile 用于确保变量的可见性，即当一个线程修改了 volatile变量的值，其他线程能够立即看到这个修改，避免线程间的缓存不一致问题。
保证原子性吗？：
- 不保证原子性。 volatile 只是确保变量的可见性，不能保证多个线程对 volatile变量的操作是原子性的。对于复合操作（如 i++ ），需要使用synchronized 或Atomic 类来保证原子性。

### threadLocal使用场景？k和v分别存储的是什么数据？为什么会发生内存泄漏？既然会发生内存泄漏，为什么要这样设计？"（中国银行-2023届秋招&&阿里&&招商银行-2022届）
使用场景：
- ThreadLocal 用于为每个线程提供一个独立的、隔离的变量副本，适合用于保存线程私有的数据，如用戶会话信息、数据库连接等。
k和v分别存储的数据：
- k： ThreadLocal 的实例。
- v：每个线程特有的数据（存储在 ThreadLocalMap 中）。
内存泄漏原因：
- ThreadLocal 的线程副本是存储在ThreadLocalMap 中的。当线程结束后，如果没有及时清理 ThreadLocal 的引用，可能导致ThreadLocal 实例和对应的值无法被垃圾回收器回收，从而造成内存泄漏。
为什么设计成这样：
- 由于线程的生命周期与 ThreadLocal 对象无关，因此，设计时故意允许存在这种风险，目的是为了更高效地为每个线程提供独立的数据副本。

### synchronized底层原理了解吗？锁升级机制是什么？轻量级锁，偏向锁了解吗？为什么会发生自旋？适用于单核cpu吗？"？（中国农业银行-2023届&&华为）
底层原理：
- synchronized 依赖于JVM的对象监视器（Monitor）实现，实际的锁操作由操作系统提供支持。
锁升级机制：
- 偏向锁：最初由单个线程获得锁，并且不释放，其他线程需要等待。
- 轻量级锁：多个线程竞争时，通过CAS操作来避免线程切换，提高性能。
- 重量级锁：当多个线程频繁竞争锁时，升级为传统的操作系统级别的互斥锁。
自旋的原因：
- 自旋锁的目的是减少上下文切换的成本，线程在获取锁之前先进行一定次数的自旋，避免直接进入阻塞状态。
- 适用于单核CPU：在单核CPU上，自旋锁通常效果较差，因为即使有空闲时间，也不能真正并行执行，可能会浪费CPU时间。

### 讲讲AQS
是一个用于实现阻塞锁和同步器的框架。它通过FIFO队列管理线程，支持多种同步器的实现，如 ReentrantLock 、 CountDownLatch 、 Semaphore 等。
原理：AQS通过内部的 state 变量和 volatile 关键字，结合CAS操作来控制线程的获取与释放，线程通过队列排队等待资源的获取。

### 什么是JMM内存模型
定义了Java程序中多个线程之间如何交互以及共享变量的访问规则。它主要解决了线程之间的可见性、原子性和有序性问题。
关键点：
- 可见性：确保一个线程修改的变量对其他线程可见。
- 原子性：保证某些操作是不可中断的。
- 有序性：保证操作的执行顺序符合预期。

### CAS是什么意思？会存在哪些问题，怎么解决？
CAS（Compare and Swap）是一种原子操作，首先比较内存中的值是否与预期相同，如果相同，则将其更新为新值，返回成功；否则返回失败。
问题：
- ABA问题：如果值被修改后又恢复原状，CAS操作可能误判为未发生变化。解决方法是引入版本号或时间戳来标记变化。
- 长时间的自旋：在高并发情况下，CAS可能会长时间自旋等待，这会导致性能问题。可以通过引入自适应的重试机制或结合其他并发工具来解决。

### ReentrantLock如何实现的公平/非公平锁？如何保证可重入？
公平锁：公平锁是指按照线程请求锁的顺序来获取锁，通常使用一个队列来管理等待的线程，保证先请求的线程先获得锁。 ReentrantLock 通过内部的 AQS（AbstractQueuedSynchronizer）机制来实现公平锁。通过设定 fair 参数为true 来创建一个公平锁： ReentrantLock(true) 。
非公平锁：非公平锁是指线程获取锁不按照请求顺序，线程可以“插队”，即如果当前没有线程持有锁，它可以直接获取锁。 ReentrantLock 默认使用非公平锁：
ReentrantLock(false) 。
可重入性： ReentrantLock 保证可重入性，意味着同一个线程可以多次获得同一个锁而不发生死锁。其实现原理是内部维护了一个 holdCount 计数器，每次线程获取锁时，holdCount 会增加；每次释放锁时， holdCount 减少，直到为0时才会真正释放锁。

### Lock和synchronized有什么异同？（滴滴三面&&交通银行-2022届春招、2024秋招）
相同点：
- 都是用于同步的工具，确保多线程环境下的共享资源不会被多个线程同时访问。
不同点：
- 灵活性： Lock 提供了更细粒度的控制，支持显式的加锁和解锁，能够实现公平锁、可中断锁等； synchronized 则是隐式锁机制，无法进行灵活的控制。
- 可中断性： Lock 可以通过 lockInterruptibly() 实现中断，而 synchronized在没有获取到锁时无法响应中断。
- 公平性： Lock 可以通过设置公平锁来确保线程的获取顺序，而 synchronized是非公平的，线程竞争时会有“插队”现象。
- 性能：在高并发场景下， Lock （尤其是 ReentrantLock ）通常比synchronized 提供更好的性能，因为它能避免不必要的上下文切换。

### FutureTask有什么作用？CompletableFuture有什么作用？两者有什么区别？
FutureTask ：

CompletableFuture ：
- 是 Future 的扩展，支持更加灵活的异步计算，提供了多个API如 thenApply() ,thenAccept() , thenCombine() 等，支持任务链式调用和组合。
- 支持非阻塞式编程，可以使用 complete() 方法手动完成任务。
区别：
- FutureTask 是 Future 接口的实现类，适用于处理简单的任务执行和结果获取。
CompletableFuture 更为强大，支持异步任务的组合、等待和响应，可以执行更复杂的操作。
- CompletableFuture 支持链式调用， FutureTask 没有这样的功能。

### 解释一下信号量机制
信号量（Semaphore）是一种用于控制访问资源的并发控制工具，它维护着一个计数器，计数器值代表了可用的资源数量。
- acquire()：请求一个资源，如果计数器大于0，则资源被分配，计数器减1；如果计数器为0，则线程阻塞。
- release()：释放一个资源，计数器加1，若有线程因资源不足阻塞，则可以唤醒一个等待线程。
信号量适用于控制多个线程对有限资源的访问，例如限制数据库连接池的最大连接数。

### CountDownLatch有什么作用
CountDownLatch是一个同步工具类，用于一个线程等待其他线程执行完毕后再执行。例如，主线程等待所有子线程完成任务再继续执行。
- 使用场景：用于协调多个线程执行顺序，如主线程等待所有子线程完成初始化操作。
- 使用方法：通过 await() 方法让线程阻塞等待， countDown() 方法使计数器减1，计数器变为0时，所有等待的线程被唤醒。

- 原子类操作都是线程安全的，能有效避免锁的使用，提升性能。

### 你怎么理解Java的IO流（中国农业银行-2024届秋招&&腾讯S3线一面）
IO流是Java提供的用于处理输入输出的机制。Java的IO流采用了流（Stream）这一概念来统一处理各种数据的输入和输出。
在Java中，IO流包括了两大类：
- 输入流（InputStream）：用于读取数据。
- 输出流（OutputStream）：用于写入数据。
通过流，我们可以处理文件、网络、内存等不同类型的数据传输。JavaIO分为字节流和字符流，用于不同的数据类型（字节流处理原始字节，字符流处理字符数据）。
JavaIO通过流的方式封装了底层的读写操作，简化了数据的处理过程。

### 什么是字节缓冲流
字节缓冲流是对字节流的包装，主要是为了提高读写性能。Java中提供了BufferedInputStream 和BufferedOutputStream 类来实现字节缓冲流。
特点：
- 使用缓冲区来存储数据，减少了每次读写时与操作系统的交互，从而提高性能。
- 当数据量较大时，直接读写会增加I/O操作的次数，而缓冲流将数据存储在缓冲区，按一定大小批量读写，减少了磁盘或网络的I/O操作次数。
使用场景：一般在读写大文件或者高频率I/O操作时，使用缓冲流可以显著提高性能。

### 字节流和字符流有什么区别？为什么有了字节流还需要字符流
⭐字节流（ByteStream）：
- 处理所有类型的I/O，包括图片、视频、音频等数据。
- 按字节读取和写入数据（ InputStream 、OutputStream ）。
- 适用于处理二进制数据。
字符流（CharacterStream）：
- 专门用于处理字符数据，采用Unicode编码格式来读写字符。
- 按字符读取和写入数据（ Reader 、 Writer ）。
- 适用于处理文本数据。
区别：
- 数据类型：字节流操作字节，字符流操作字符，字符流在字节流的基础上进行了字符编码的转换，能自动处理字符的编码和解码（例如UTF-8、GBK）。
- 适用范围：字节流适合所有类型的文件，字符流仅适用于文本文件。
为什么有了字节流还需要字符流：
- 字节流直接处理字节，对于文本文件需要手动处理字符的编码和解码，不够方便。字符流则自动处理字符集和编码转换，简化了字符数据的读写操作，提高了对文本数据的处理效率和可读性。
- 如果操作纯文本数据，使用字符流更为高效，因为字符流会自动对文本进行编码解码，不需要开发者额外处理。

### BIO是什么？
BIO（BlockingI/O）是传统的I/O模型，指的是每一次I/O操作都会阻塞当前线程，直到操作完成才会返回结果。
特点：
- 阻塞：线程会在进行I/O操作时被阻塞，直到数据完全读入或者写出。
- 线程一一对应：每个连接都需要一个独立的线程进行处理，如果并发量很高，容易造成线程上下文切换开销，影响性能。
使用场景：适用于请求量较小、并发不高的系统。

### NIO是什么？（中国农业银行-2024届秋招&&腾讯S3线一面招商银行-2024届秋招）
NIO（NewI/O）是Java1.4引入的新I/O模型，旨在提升I/O操作的效率，解决BIO的性能问题。
特点：
- 非阻塞：NIO允许线程非阻塞地处理I/O操作，即线程可以在等待数据时执行其他任务。
- 选择器（Selector）：通过 Selector实现单个线程管理多个I/O通道，从而减少了线程数量，降低了资源消耗。
- 通道（Channel）：NIO引入了 Channel 接口，支持高效的读写操作。
- 缓冲区（Buffer）：NIO通过 Buffer 类来读写数据，数据的读写从传统的流改为通过缓冲区直接操作内存，提高了效率。
使用场景：NIO适合高并发、高性能的网络和文件I/O操作，如Web服务器、文件传输等。

### AIO是什么？
AIO（AsynchronousI/O）是Java7引入的异步I/O模型，提供了对非阻塞I/O操作的进一步优化，允许线程在I/O操作中不阻塞，也不需要轮询。
特点：
- 完全异步：通过回调机制，I/O操作完成后会通知相关的线程继续执行，不需要显式的阻塞。
- 提高性能：AIO可以进一步减少线程的上下文切换，因为I/O操作是完全异步进行的，线程仅在I/O操作完成后进行处理。
使用场景：AIO适用于对I/O操作要求极高的系统，如高并发的网络应用、实时处理系统等。

### JavaIO中有哪些设计模式？
装饰者模式（DecoratorPattern）：
- JavaIO中的流（如 BufferedReader 、 FileReader ）就是典型的装饰者模式。通过装饰器可以对基本流功能进行扩展或增强，比如对文件的读取进行缓冲、对输入进行加密等。
适配器模式（AdapterPattern）：
- InputStreamReader 和 OutputStreamWriter 将字节流和字符流连接起来，它们充当了字节流和字符流之间的适配器，使得二者可以互通。
工厂模式（FactoryPattern）：
- Stream 类提供了各种创建流对象的方法，像 FileInputStream 、FileOutputStream 等，都可以看作是流的工厂方法，隐藏了具体的实现细节。
策略模式（StrategyPattern）：
- 在文件I/O处理过程中， Reader 和 Writer 类的实现可以通过不同策略（如缓冲区的大小，字符编码方式）来进行选择，不同的策略用于不同场景，提高了代码的灵活性和可维护性。

- 选择性高的列：为选择性高的列（即不同值的数量多的列）建立索引，能够显著提高查询效率。
- 避免为小表创建索引：小表的查询操作速度已经较快，索引反而会增加维护成本。
- 避免过多索引：虽然索引能加速查询，但它也会影响数据的插入、更新、删除操作的效率。
优化索引的方式：
- 使用前缀索引：对于长字符串列，使用前缀索引可以减少索引存储空间。
- 覆盖索引：当查询的字段都能在索引中找到时，可以避免回表查询，极大提升查询性能。
- 避免多余的索引：删除不常用的索引，减少存储空间和维护开销。

### 什么时候会导致索引失效？最左匹配原则是什么，为什么需要满足最左匹配"？（交通银行-2024届秋招&&滴滴&&华为&&招商银行-2024届）
索引失效的常见原因：
- 列的顺序不匹配：联合索引遵循最左匹配原则，查询条件没有按照索引列的顺序进行，会导致索引失效。
- 使用 LIKE 操作符不以常量开头：例如 LIKE '%abc' ，会导致索引失效。
- 在条件中进行计算：例如 WHERE YEAR(date_col) = 2020 ，会导致索引失效。
- 使用 IS NULL 条件：如果查询使用了IS NULL ，某些情况下索引可能会失效。
最左匹配原则：
- 在使用联合索引时，必须从索引的最左边开始使用连续的列进行查询，才能保证索引的有效性。
- 例如， index(a, b, c) ，查询条件是 a = 1 AND b = 2 ，索引会生效；如果查询条件是 b = 2 AND c = 3 ，则索引会失效，因为没有使用最左的列a 。

### Mysql有哪些索引类型？聚簇索引和非聚簇索引有什么区别？（中国工商银行-2024届春招&&美团&&蚂蚁&&中国农业银行-2024届&&交通银行-2023届秋招）
索引类型：
- 普通索引（Index）：最基本的索引类型，允许索引列有重复值。
- 唯一索引（UniqueIndex）：索引列的值必须唯一，但允许 NULL值。
- 主键索引（PrimaryKey）：特殊的唯一索引，不能为 NULL ，每个表只能有一个主
- 键。全文索引（FulltextIndex）：主要用于文本搜索，可以加速对文本内容的查询。
- 空间索引（SpatialIndex）：用于地理信息数据，支持空间查询。
聚簇索引和非聚簇索引的区别：
- 聚簇索引：表中的数据按照索引的顺序存储，数据和索引是存储在同一结构中的。每个表只能有一个聚簇索引（InnoDB表的主键索引就是聚簇索引）。

### 什么时候会发生回表查询？（中国工商银行-2023届&&腾讯一面）
回表查询发生在使用非覆盖索引时。即查询的字段不包含在索引中，查询需要从索引中找出记录的行指针，然后通过回表查找实际的数据行。
例子：如果创建了 (a, b) 的联合索引，但查询时只用了 a 并且需要查询 c 列，这时需要通过回表查询 c 的值。

### 什么时候会触发filesort

避免filesort：
- 确保查询中的 ORDER BY 字段有合适的索引。
- 使用 LIMIT 来减少数据量。

### mysql事务有什么特性，怎么实现？（中国农业银行-2024届&&交通银行-2023届秋招）
事务特性（ACID）：
- 原子性（Atomicity）：事务中的操作要么全部执行成功，要么全部不执行。
- 一致性（Consistency）：事务开始和结束时，数据库的状态应该是一致的。
- 隔离性（Isolation）：事务的执行不受其他事务干扰，事务之间是隔离的。
- 持久性（Durability）：事务一旦提交，其对数据库的改变是永久性的，即使系统崩溃也不丢失。
实现方式：
- MySQL通过 InnoDB 引擎来实现事务。事务通过 BEGIN 开始， COMMIT 提交，ROLLBACK 回滚。
- MySQL还支持不同的事务隔离级别（如 READ UNCOMMITTED 、 READCOMMITTED 、 REPEATABLE READ 、SERIALIZABLE ）来保证事务之间的隔离性。

### mysql中一行数据是怎么存储的
在InnoDB存储引擎中，每一行数据存储在一个数据页（Page）中，通常每个数据页大小为16KB。
数据行的存储方式根据表的字段类型不同而有所不同，整型、浮动类型、字符串等字段占用不同的字节数。
每一行数据通常包括数据的实际内容和一些控制信息（如行锁、NULL位图等）。
如果使用聚簇索引（主键索引），数据行按照主键顺序存储，并且主键和数据存储在同一页面。

### mysql隔离级别，分别会出现什么问题？mysql通过什么去保证隔离级别"？（中国农业银行-2023届&&蚂蚁&&淘天）
隔离级别：
- READUNCOMMITTED：事务可以读取未提交的事务数据（脏读），可能导致脏数据。
- READCOMMITTED：事务只能读取已提交的事务数据（不可重复读），但可以发生不可重复读。
- REPEATABLEREAD：事务在执行过程中多次读取相同数据时，结果一致（不可重复读），但可能发生幻读。
- SERIALIZABLE：事务完全隔离，串行化执行，避免脏读、不可重复读和幻读。
保证隔离级别的方式：
- MySQL通过锁机制（行锁、表锁）来实现事务的隔离级别，确保事务按照设定的隔离级别进行执行。

### 讲讲Mysql集群，主从同步的流程，有哪几种主从同步的方式
MySQL集群：
- MySQL集群是一种高可用的解决方案，可以通过多台MySQL服务器来分担负载，保证高可用性和可扩展性。常见的有主从复制、组复制等方案。
主从同步流程：
- 主服务器（Master）上执行写操作后，将这些操作记录在二进制日志中。
- 从服务器（Slave）通过读取主服务器的二进制日志，并将这些日志应用到自己的数据上，从而保持数据同步。
主从同步方式：
- 异步复制：从服务器在接收到主服务器的日志后，延迟将其应用到自己的数据上，不保证同步的实时性。
- 半同步复制：主服务器会等待至少一个从服务器确认接收到数据，才会提交事务。
- 同步复制：所有的从服务器必须接收到并应用日志后，主服务器才会提交事务，保证完全一致性。

### Mysql什么情况下可能产生死锁？如何排查？
死锁情况：
- 死锁发生在两个或多个事务相互等待对方释放锁，从而造成无休止的等待。
- 典型情况是两个事务分别锁住资源1和资源2，事务A请求资源2时阻塞，事务B请求资源1时也阻塞，形成死锁。
排查方法：
- 启用 SHOW ENGINE INNODB STATUS 查看死锁信息。
- 分析死锁日志，检查参与死锁的SQL语句，查找死锁发生的原因。
- 可以设置 innodb_deadlock_detect 为1启用死锁检测，及时发现并回滚死锁事务。

### MVCC是为了解决什么问题，怎么实现的
解决的问题：
- MVCC（多版本并发控制）主要用于解决数据库中的读写冲突问题，尤其是在高并发环境下，避免读操作阻塞写操作以及写操作阻塞读操作，提供高效的并发读写能力。
实现方式：
- 每次事务对数据进行修改时，都会为数据创建一个新版本（并不会直接修改原数据）。
- 通过时间戳或事务ID来标识数据的版本，每个事务只能看到它开始时可见的版本数据。
- 读取时通过判断数据的版本来决定是否能读取该数据，确保不同事务之间的隔离。

### 可重复读的隔离级别下，能完全解决幻读问题吗？（中国农业银行-2023届&&招商银行-2025届&&PDD）
能否完全解决幻读问题：
- 在可重复读（REPEATABLEREAD）隔离级别下，无法完全解决幻读问题。
- 幻读指的是在同一个事务内，多次查询相同条件的数据，但结果可能因为其他事务的插入操作而有所不同。
- 可重复读会保证在事务期间，相同的查询总是返回相同的数据，但如果事务进行查询时，其他事务插入了新的数据，仍然可能造成幻读。
- InnoDB通过Next-KeyLock来锁定记录，并一定程度上减少幻读，但无法完全避免。

### binlog格式有哪些？刷盘策略是怎样的？
binlog格式：
- ROW：记录行级别的变化，精确记录每一行数据的变化。
- STATEMENT：记录SQL语句，通常只记录引发数据变化的SQL语句。
- MIXED：混合模式，MySQL根据情况自动选择使用ROW或STATEMENT格式。
刷盘策略：
- 同步刷新： sync_binlog 配置项控制，每当binlog 缓冲区写满或执行完某个事务时，就会将 binlog 刷新到磁盘。
- 异步刷新：在某些情况下，MySQL并不会立即将 binlog 写入磁盘，而是依赖操作系统的缓存，直到缓存满或发生故障时才刷新。

### redolog刷盘策略是怎样的？写满了会怎么样
Redolog刷盘策略：
- 每次事务提交时，MySQL会先将事务的redo日志写入日志文件，并刷新到磁盘，确保事务的持久性。
- 刷盘间隔：通过 innodb_flush_log_at_trx_commit 参数控制：
   - 1 ：每次提交时刷新日志（最安全，性能最差）。
   - 2 ：每次提交时将日志写入磁盘，但不刷新。
   - 0 ：每秒刷一次日志。
写满了会怎么样：
- 如果redolog写满，会覆盖最早的日志，保证事务的继续进行。
- 需要保证 innodb_log_file_size 配置合理，避免频繁覆盖或日志丢失。

### binlog和redolog有什么区别，为什么有了binlog还要redolog
binlog与redolog的区别：
- binlog：记录所有导致数据库状态变化的SQL语句，主要用于数据恢复和主从同步。
- redolog：记录事务提交前的数据修改，主要用于崩溃恢复，确保事务的持久性。
为什么有binlog还要redolog：
- binlog用于复制和数据恢复，而redolog用于保证事务的持久性和崩溃恢复。
- Binlog是基于语句的，而Redolog是基于数据的操作，这两者相辅相成，保证数据的安全性与可靠性。

### undolog和redolog有什么区别
undolog：
- 用于回滚事务，记录数据的反向操作，帮助恢复数据到事务开始之前的状态。
- 主要用于事务中的数据回滚。
redolog：
- 用于持久化事务日志，记录事务的所有修改操作，确保数据的一致性。
- 主要用于事务提交后的数据持久化。

### 描述一条sql语句具体的执行，以及写日志的流程
SQL语句执行流程：
身份验证---缓存---
1. 查询解析：MySQL将SQL语句解析为执行计划，检查语法和逻辑错误。

### Mysql中的BufferPool有什么作用？脏页什么时候会被刷到磁盘？如果宕机了会丢数据吗？怎么
解决的"BufferPool作用：
- BufferPool是InnoDB的内存缓存区域，用于缓存表数据和索引，减少磁盘I/O，提高查询效率。
脏页刷盘：
- 脏页是指内存中已修改，但尚未同步到磁盘的页面。

### 讲讲binlog和redolog的两阶段提交
两阶段提交流程：
1. 第一阶段：在事务提交时，MySQL会先将事务的修改记录到redolog中，并刷新到磁盘，确保事务的持久性。
2. 第二阶段：提交后，MySQL将相关的binlog同步到磁盘，并通过二进制日志的传输，通知其他节点执行同步操作。
- 这确保了事务提交的原子性，并为后续的主从同步和数据恢复提供支持。

### 缓存穿透，缓存雪崩，缓存击穿了解吗，分别怎么解决？（交通银行-2025届秋招&&淘天&&字节）
缓存穿透：
- 问题：查询的请求在缓存和数据库中都没有结果，导致每次请求都直接访问数据库，影响性能。
- 解决：使用布隆过滤器，提前判断某个查询是否存在，避免无效的查询进入数据库。
缓存雪崩：
- 问题：缓存中大量数据在同一时间过期，导致大量请求直接访问数据库。
- 解决：设置合理的过期时间，并通过加随机值、分布式锁等手段来避免大规模缓存失效。
缓存击穿：
- 问题：某个热点数据突然失效，导致并发请求访问数据库，造成数据库压力过大。
- 解决：使用互斥锁、标志位等方式，确保只有一个线程访问数据库并加载数据到缓存。

- 扩展性差：本地缓存只在当前进程内有效，难以扩展到多台机器。

### redis的持久化机制有哪些？AOF日志和RDB日志有什么区别？"（邮政储蓄银行-2024届秋招&&字节&&网易）
持久化机制：
- RDB（快照）：定期生成数据的快照，并保存到磁盘，适用于数据恢复。缺点是如果在快照之间发生故障，可能丢失数据。
- AOF（追加文件）：记录每一次写操作到日志文件中，能保证数据不丢失，恢复时会根据AOF日志重放操作。缺点是日志文件可能会变得非常大，且恢复速度较慢。
区别：
- RDB：适合数据恢复快、性能优先的场景，但可能会丢失部分数据。
- AOF：提供更高的数据安全性，适合需要强一致性和数据不丢失的场景，但性能开销较大。

### 如果使用redis作缓存，怎么保证双写一致的问题？（滴滴&&小红书&&中国银行-2023届秋招&&阿里）
双写一致性问题：当数据库和缓存同时更新时，如何保证二者的数据一致性。
解决方案：
- 缓存更新策略：当数据在数据库中更新时，同时更新缓存中的数据（通常使用set / del 操作）。
- 延迟双删：在缓存更新时，先删除缓存，再更新数据库，数据库更新完成之后再删除缓存
- 消息队列：通过消息队列异步更新缓存和数据库，确保最终一致性。

### redis如何保证高可用，如何进行主从同步？
高可用：
- Redis通过主从复制、Sentinel和Cluster等机制保证高可用。
主从同步：
- 主从复制：一个主节点和多个从节点，主节点将写操作同步到从节点，实现数据的复制。
读请求可以分担到从节点上，提升系统的可用性。
- Sentinel：RedisSentinel提供监控、自动故障转移和通知功能，当主节点宕机时，Sentinel会自动选举出新的主节点。

### 主节点宕机如何选举新的主节点
选举机制：
- RedisSentinel会监控主节点的健康状态，当发现主节点宕机时，会通过投票机制选举一个从节点作为新的主节点。
- 选举过程包括：
a. Sentinel检测到主节点宕机。
b. Sentinel通知其他Sentinel进行选举。
c. 如果大多数Sentinel同意，选举新的主节点。
d. 新主节点将开始接收写请求，原从节点自动成为新的从节点。

### 什么是集群脑裂问题
脑裂问题：
- 在Redis集群中，脑裂指的是集群中的多个节点因为网络分裂或故障，无法相互通信，导致每部分都认为自己是集群的主节点，进而导致数据不一致的问题。
解决方案：
- Redis通过Quorum机制和一致性协议来避免脑裂问题，确保只有一个主节点在集群中具有写权限

### 多大算大key，会导致什么问题，怎么解决
什么是大key：

- 使用更小的粒度：对于有大量数据的场景，使用Redis的分片或持久化方案来避免大key的直接存储。

### qps多少算热key，会导致什么问题，怎么解决
热key的定义：

- 缓存雪崩：大量请求集中到某个热key，导致缓存压力过大。
- 单点压力：热key的读写压力集中到某个Redis实例或节点，可能导致该节点的性能瓶颈或宕机。
- Redis性能下降：热key可能使Redis的单线程机制成为瓶颈，影响系统整体性能。
解决方案：
- 数据分片：使用Redis集群或分片策略，将热点数据分散到多个节点，减轻单点压力。
- 异步处理：对于热key的写操作，可以通过异步写入等方式，降低Redis的读写压力。
- 限流：通过限流措施减少对热key的请求频率，避免超载。

### redis如何实现分布式锁？可能会出现哪些问题，怎么解决？红锁了解吗？（中国工商银行-2024届春招&&阿里巴巴&&蚂蚁）
分布式锁的实现：
- Redis分布式锁一般使用 SETNX （setifnotexists）命令，确保只有一个客戶端可以获得锁。
- 锁的基本流程是：客戶端使用 SETNX 设置一个带有唯一标识的键值，并设置过期时间，防止死锁。
可能出现的问题：
- 死锁：客戶端获得锁后崩溃或停止工作，导致锁无法释放。
- 锁失效：如果设置的过期时间过短，锁可能会在业务完成前过期，导致其他客戶端抢占锁。（看门狗机制）
解决方案：
- 设置合理的过期时间：根据业务处理时间设置锁的过期时间。
- 释放锁时的检查：释放锁时确保只有持有锁的客戶端才能释放，避免误删。
- 使用红锁：Redlock是由Antirez（Redis的作者）提出的分布式锁算法，基于多个Redis实例来增强锁的可靠性，减少单点故障的风险。

### redis中的内存淘汰策略
Redis提供了几种内存淘汰策略，适用于不同的内存使用情况：
- noeviction：不淘汰任何数据，内存满时请求会报错。
- allkeys-lru：使用LRU（LeastRecentlyUsed）算法删除最少使用的key。
- volatile-lru：仅对设置了过期时间的key使用LRU策略。
- allkeys-random：随机删除key。
- volatile-random：仅对设置了过期时间的key随机删除。
- volatile-ttl：优先删除那些剩余生存时间较短的key。

- Redis会定期扫描过期的键，并将其删除。如果启用了RDB/AOF持久化机制，过期的键会在下一次持久化时被移除。

### redis是单线程为什么快?（招商银行-2025届&&中国农业银行-2024届秋招&&滴滴）

- Redis使用单线程模型，避免了线程切换和锁的开销。单线程意味着没有上下文切换，减少了CPU的时间开销。
高效性：
- Redis通过I/O多路复用（epoll/select）机制来同时处理多个客戶端请求，能够高效地利用单线程，达到高并发的性能。
- 内存操作速度非常快，几乎没有磁盘I/O操作。

- AOF持久化：将写命令追加到AOF日志文件中，后台线程会定期刷新日志。
- RDB持久化：在指定的时间间隔内，将内存中的数据生成快照并保存到磁盘。

- poll：比select更强大，支持更多的文件描述符。
- epoll：Linux下最常用的I/O多路复用方式，支持大量的并发连接，具有高效的事件通知机制。
- kqueue：BSD系统上的多路复用实现，类似于epoll。

### mybatis缓存机制是怎么样的，两级缓存分别在什么时候用

- 也称为本地缓存，是MyBatis默认启用的缓存，作用范围是SqlSession的生命周期。
- 在同一个SqlSession中，查询的结果会被缓存，避免了重复的数据库查询操作。
- 当SqlSession关闭后，一级缓存会被清空。
二级缓存：
- 也称为全局缓存，作用范围是MyBatis的全局配置（多个SqlSession共享）。
- 二级缓存是可配置的，可以存储跨SqlSession的查询结果，从而减少数据库的压力。
- 必须显式配置，在配置文件中启用二级缓存，并且要配置缓存的存储策略（例如内存或磁盘）。

3. 自动映射：根据配置的映射规则，将查询结果自动映射成Java对象。
4. 提交事务：在非自动提交模式下，执行完数据库操作后，需要显式提交事务。
5. 关闭SqlSession：执行完操作后，关闭SqlSession，释放资源。

### SpringMVC是什么？
SpringMVC是一个基于Java的Web框架，是Spring框架的一部分，旨在简化Web应用程序的开发。它遵循MVC（Model-View-Controller）设计模式，将Web应用分为模型、视图和控制器三个部分，帮助开发者解耦业务逻辑和显示逻辑。SpringMVC提供了灵活的架构和丰富的功能，使得开发Web应用变得更加简洁高效。
核心特性：
- 强大的请求映射功能。
- 灵活的视图解析功能。
- 支持RESTful风格的Web服务。
- 简化了表单处理、数据验证、错误处理等操作。

### SpringMVC的执行流程是怎样的？（中国农业银行-2023届&&中国农业银行-2024届秋招&&PDD&&阿里云）
SpringMVC的执行流程可以分为以下几个主要步骤：
1. 用戶请求：客戶端发起请求，浏览器通过HTTP向服务器发送请求。
2. 前端控制器（DispatcherServlet）：所有的请求首先会进入SpringMVC的前端控制器DispatcherServlet 。它负责接收请求并将请求转发到相应的处理器（Controller）。
3. 处理映射（HandlerMapping）： DispatcherServlet 根据请求的URL调用相应的Controller方法。HandlerMapping 根据请求的URL找到相应的处理器方法。
4. 处理器（Controller）： DispatcherServlet 调用 Controller 的处理方法来处理请求，业务逻辑在此完成。
5. 视图解析（ViewResolver）： Controller 执行完逻辑后，会返回一个视图名称，DispatcherServlet 会通过 ViewResolver 查找对应的视图页面（如JSP、HTML等）。
6. 渲染视图：视图被渲染，数据填充到视图中，最终呈现给客戶端。

### SpringMVC有哪些重要组件
SpringMVC的核心组件包括：
1. DispatcherServlet：前端控制器，所有请求都通过它进行分发。
2. HandlerMapping：处理器映射器，用来将请求与相应的处理器（Controller方法）映射。
3. Controller：处理用戶请求的控制器，包含处理业务逻辑的方法。
4. ViewResolver：视图解析器，负责将返回的视图名称解析为实际的视图。
5. HandlerInterceptor：拦截器，用于在请求处理之前和之后做一些处理（如日志、权限验证等）。
6. ModelAndView：用于传递模型数据和视图信息。
7. @Controller,@RequestMapping等注解：SpringMVC中使用的注解，帮助映射请求到控制器的方法。

### SpringMvc有哪些常用注解？（中国农业银行-2023届&&交通银行-2024届春招&&阿里云&&携程）
SpringMVC提供了多个常用注解来简化开发：
1. @Controller：标记一个类是Controller类，接收用戶请求并处理业务逻辑。
2. @RequestMapping：映射HTTP请求到Controller的方法，支持请求的URL、请求方法、请求参数等的映射。
3. @GetMapping、@PostMapping、@PutMapping、@DeleteMapping：分别处理HTTPGET、POST、PUT、DELETE请求。
4. @RequestParam：用于获取请求参数。
5. @PathVariable：从URL中获取动态参数。
6. @RequestBody：将HTTP请求体的内容绑定到方法的参数上（通常用于处理JSON请求）。
7. @ResponseBody：将方法返回值直接写入HTTP响应体，通常用于处理JSON响应。
8. @ModelAttribute：将请求参数绑定到方法的参数对象上。
9. @SessionAttributes：将模型对象保存到Session中，通常用于跨请求保持数据。

### 如何实现SpringMVC拦截器
SpringMVC拦截器是通过实现HandlerInterceptor 接口来实现的，常用于请求前后做一些公共的处理（如日志记录、权限验证等）。拦截器有三个主要方法：
1. preHandle：在请求处理之前执行，返回true 表示继续请求流程，返回 false 表示请求终止。
2. postHandle：在请求处理之后执行，视图渲染之前调用。
3. afterCompletion：在请求处理和视图渲染之后执行，主要用于资源清理。
实现步骤：
1. 创建一个拦截器类，继承 HandlerInterceptor 接口。
2. 实现 preHandle 、 postHandle 、 afterCompletion 方法。
3. 在Spring配置文件（XML）或 @Configuration 注解的Java配置类中注册拦截器。

### 什么是springmvc的父子容器
SpringMVC的父子容器机制允许开发者根据需求在不同的容器之间进行管理。Spring容器有一个根容器（父容器）和多个子容器。SpringMVC中的父子容器模式主要表现在：
1. 父容器：负责管理Spring框架的核心功能，如 BeanFactory 、ApplicationContext 、数据库连接池等全局配置。
2. 子容器：每个子容器可以拥有自己的配置，用来处理特定的业务逻辑。子容器通常继承父容器的配置，并且可以覆盖父容器的某些设置。
父子容器机制使得Spring能够实现模块化配置，不同的子容器可以独立配置和管理各自的Bean，而父容器负责提供全局资源。这对于大型项目中的分布式应用非常有用，可以实现灵活的配置和隔离。

### properties，yml，yaml配置文件有什么区别，加载优先级是怎样的

2. application.yml 或 application.yaml

4. @Value 注解等代码内的配置。

### 讲讲SpringBoot自动装配原理？（邮政储蓄银行-2024届秋招&&中国农业银行-2024届秋招&&淘天&&字节）
SpringBoot的自动装配（AutoConfiguration）机制是其核心特性之一，旨在简化Spring应用的配置过程。其原理如下：
1. @EnableAutoConfiguration 注解：通过该注解，SpringBoot启动了自动装配机制。该注解会引入 AutoConfigurationImportSelector ，并根据当前项目的类路径和配置文件，选择合适的配置类进行自动装配。
2. @Conditional 注解：自动装配的核心是通过 @Conditional注解进行条件判断，只有满足特定条件时，相关的自动配置才会生效。例如：
   - @ConditionalOnClass ：当某个类存在时，才会自动装配。
   - @ConditionalOnMissingBean ：当容器中没有指定的Bean时，才会自动装
   - 配。@ConditionalOnProperty ：当某个属性配置存在且满足条件时，才会自动装
配。
3. META-INF/spring.factories 文件：SpringBoot通过 spring.factories 文件来加载自动配置类。自动配置类通常包含在 spring-boot-autoconfigure 模块中，通过该文件进行注册。
4. 配置与约定：SpringBoot根据项目中引入的依赖、配置文件及开发者提供的自定义设置，自动进行配置，减少手动配置的工作量。例如，如果项目中引入了 spring-boot-starter-data-jpa ，SpringBoot会自动配置JPA相关的组件。
5. 自定义自动配置：开发者可以通过创建自定义的自动配置类，并在 @Configuration类中添加 @EnableAutoConfiguration ，来扩展SpringBoot的自动装配功能。
